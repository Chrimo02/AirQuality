Dockerfile Frontend - CM

Zweck und Kontext

Dieses Dockerfile baut das Frontend des Projekts Airquality-Monitoring als optimierte, statische Web-Applikation in einer isolierten Umgebung. Es nutzt einen zweistufigen Build-Prozess, um ein schlankes und performantes Produktions-Image bereitzustellen. Das finale Image läuft mit dem Webserver NGINX, welcher die fertigen statischen Dateien bereitstellt.

Dockerfile-Inhalt

# Build Stage
FROM node:18-alpine as build
WORKDIR /app
COPY . .
RUN npm install
RUN npm run build

# Production Stage
FROM nginx:alpine
COPY --from=build /app/build /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]


Erläuterung der einzelnen Anweisungen

FROM node:18-alpine as buildNutzt ein leichtgewichtiges Node.js-Image (Alpine) in Version 18 als Build-Umgebung.
WORKDIR /appSetzt das Arbeitsverzeichnis innerhalb des Containers auf /app.
COPY . .Kopiert den gesamten Frontend-Quellcode in das Arbeitsverzeichnis.
RUN npm installInstalliert alle Abhängigkeiten aus package.json.
RUN npm run buildErzeugt optimierte, statische Dateien für die Produktionsumgebung.
FROM nginx:alpineStartet eine neue, schlanke Laufzeit-Umgebung basierend auf NGINX-Alpine.
COPY --from=build /app/build /usr/share/nginx/htmlKopiert die generierten statischen Dateien aus dem vorherigen Build-Schritt in das NGINX-Standardverzeichnis.
EXPOSE 80Macht Port 80 für HTTP-Anfragen zugänglich.
CMD ["nginx", "-g", "daemon off;"]Startet den NGINX-Webserver im Vordergrund (Standard für Container-Betrieb).

Hinweise zur Wartbarkeit

  • Änderungen der Frontend-Abhängigkeiten müssen immer in der package.json definiert sein.

  • Bei größeren Änderungen ist ein regelmäßiger Cleanup (npm prune oder Ähnliches) ratsam, um Abhängigkeiten aktuell und sicher zu halten.

Zusammenfassung

Das Dockerfile baut und betreibt das Frontend als schlanke, effiziente Web-Anwendung auf Basis von NGINX. Durch die Nutzung von Multi-Stage Builds wird das resultierende Image klein und ideal für den Einsatz in Produktionsumgebungen optimiert.
