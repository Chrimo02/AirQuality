MQTT-Publishing vom Raspberry Pi - CM

Ziel

Das Ziel war, die bestehende API (api.py, FastAPI-basiert) so zu erweitern, dass kontinuierlich das aktuelle Luftqualitätslevel via MQTT gepublisht wird. Um Robustheit zu gewährleisten, sollte die API zudem automatisch versuchen, eine verlorene MQTT-Verbindung wiederherzustellen.

Umsetzung

Die Implementierung erfolgte direkt in der vorhandenen api.py und umfasst folgende Aspekte:

1. Initialisierung des MQTT-Clients

Beim Start der API wird der MQTT-Client initialisiert und verbindet sich mit dem lokalen MQTT-Broker:


@app.on_event("startup")
async def startup_event():
    global mqtt_client

    try:
        mqtt_client = MQTTClient(MQTT_BROKER, MQTT_PORT, MQTT_TOPIC)
        print(f"MQTT Client verbunden mit {MQTT_BROKER}:{MQTT_PORT}, Topic: {MQTT_TOPIC}")
    except Exception as e:
        print(f"MQTT Client konnte nicht verbunden werden: {e}")
        mqtt_client = None

    asyncio.create_task(live_data_loop())
    asyncio.create_task(mqtt_reconnect_loop())


2. Kontinuierliches Publishing der Luftqualität

Im bestehenden live_data_loop() werden regelmäßig Sensordaten verarbeitet und das ermittelte Luftqualitätslevel per MQTT veröffentlicht:


async def live_data_loop():
    global mqtt_client

    while True:
        try:
            raw_line = sensor_reader.lese_daten()
            if not raw_line:
                await asyncio.sleep(1)
                continue

            rating_vals = sensor_reader.get_rating_measurements(raw_line)
            rules = get_air_quality_rules()
            overall_quality = rules.get_overall_air_quality(rating_vals)
            overall_quality_str = air_quality_to_string(overall_quality)

            if mqtt_client:
                try:
                    mqtt_client.publish(overall_quality_str)
                except Exception as e:
                    print(f"Fehler beim MQTT Publish: {e} - MQTT Client wird neu verbunden")
                    mqtt_client = None  # Löst reconnect aus

        except Exception as e:
            print(f"Error in live data loop: {e}")

        await asyncio.sleep(1)


3. Automatische Wiederverbindung zum MQTT-Broker

Der Task mqtt_reconnect_loop() sorgt dafür, dass der MQTT-Client, falls die Verbindung verloren geht, automatisch alle 30 Sekunden versucht, sich erneut mit dem Broker zu verbinden:


async def mqtt_reconnect_loop():
    global mqtt_client

    while True:
        if mqtt_client is None:
            try:
                mqtt_client = MQTTClient(MQTT_BROKER, MQTT_PORT, MQTT_TOPIC)
                print(f"[MQTT] Reconnected to broker at {MQTT_BROKER}:{MQTT_PORT}")
            except Exception as e:
                print(f"[MQTT] Reconnect failed: {e}")
        await asyncio.sleep(30)


Funktionsweise und Vorteile

  • Robustheit: Bei temporären Verbindungsproblemen oder einem Neustart des Brokers baut die API die Verbindung automatisch wieder auf.

  • Performance: Die asynchronen Tasks beeinflussen die Performance der restlichen API-Endpunkte nicht spürbar.

  • Zuverlässigkeit: Externe Systeme (z. B. LED-Indikatoren oder Dashboards), die MQTT-Nachrichten abonnieren, erhalten kontinuierlich aktuelle Luftqualitätsdaten, auch bei kurzen Unterbrechungen.

Fazit

Durch diese Integration wird eine stabile und wartungsarme Bereitstellung aktueller Luftqualitätsdaten über MQTT ermöglicht, ohne den laufenden Betrieb der API negativ zu beeinflussen.
