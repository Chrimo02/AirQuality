Containerisierung mit Docker Compose - PP

1. Übersicht

Das gesamte System läuft als Docker-Compose-Stack und besteht aus folgenden Komponenten:

  • Backend (API):
    FastAPI (Python), Zugriff auf den Luftqualitätssensor via USB.

  • Frontend:
    Modernes SPA-Framework (z. B. Vite/React/Vue), Build-Argumente erlauben flexible API-URL.

  • SQLite-Datenbank:
    Persistente Speicherung im lokalen Host-Ordner, unabhängig von Containern.

2. docker-compose.yml (finales Setup)

version: "3.9"
services:
  api:
    build:
      context: .
      dockerfile: DOCKERFILE.backend
    container_name: airquality-api
    ports:
      - "8000:8000"
    volumes:
      - ./database:/app/database      # SQLite-DB bleibt erhalten!
    environment:
      - PYTHONUNBUFFERED=1
    restart: unless-stopped
    devices:
      - "dev/ttyUSB0:/dev/ttyUSB0"

  frontend:
    build:
      context: ../frontend
      dockerfile: DOCKERFILE.frontend
      args:
        VITE_USE_MOCK: ${VITE_USE_MOCK:-false}
        VITE_API_URL:   ${VITE_API_URL:-http://172.20.10.4:8000}
    container_name: airquality-frontend

    ports:
      - '3000:80'
    restart: unless-stopped
    depends_on: 
      - api

    environment:
      - VITE_USE_MOCK=${VITE_USE_MOCK:-false}
      - VITE_API_URL=${VITE_API_URL:-http://172.20.10.4:8000}

3. Erläuterungen zu den wichtigsten Optionen

api-Service:

  • devices:
    /dev/ttyUSB0 wird in den Container gemountet, damit der Sensor auch im Container direkt angesprochen werden kann.

  • volumes:
    Das lokale Verzeichnis ./database speichert die SQLite-Datenbank persistent und unabhängig vom Container-Lebenszyklus.

  • ports/environment/restart:
    Die API läuft auf Port 8000. Bei Fehlern/Neustarts wird der Container automatisch wieder gestartet.

frontend-Service:

  • build/context/dockerfile:
    Baut das Frontend aus dem ../frontend-Verzeichnis mit dem angegebenen Dockerfile.

  • args/environment:
    Die Variable VITE_API_URL verweist fest auf die interne API-IP (http://172.20.10.4:8000).
    Damit ist die API von allen Geräten im selben Netzwerk aus erreichbar – wichtig für echte Mehrgeräte-Umgebungen!

  • depends_on:
    Das Frontend wird erst gestartet, wenn die API verfügbar ist.

4. Start und Nutzung

Stack starten:

docker-compose up --build

  • API erreichbar:
    http://172.20.10.4:8000

  • Frontend erreichbar:
    http://localhost:3000 (bei Zugriff auf dem Host)

5. Besonderheiten und Tipps

  • Die feste API-URL (VITE_API_URL) sorgt dafür, dass das Frontend im Container immer die richtige Adresse für das Backend kennt – sowohl im lokalen Netzwerk als auch für mobile/weitere Geräte.

  • Der USB-Sensor funktioniert im Container, da /dev/ttyUSB0 direkt eingebunden wird.

  • Die Datenbank bleibt immer im lokalen Ordner und ist somit leicht für Backups oder externe Analysen zugänglich.
