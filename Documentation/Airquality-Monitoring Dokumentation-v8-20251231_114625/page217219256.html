MQTT-Setup Troubleshooting - CM

Troubleshooting am Raspberry Pi:

Wenn beim Start des Mosquitto-Brokers MQTT-Clients aus dem LAN beim Verbindungsversuch die Meldung „Connection refused“ angezeigt wird, liegt das häufig daran, dass der Dienst standardmäßig nur auf der Loopback-Schnittstelle (localhost) lauscht und anonyme Verbindungen unterbindet. Abhilfe schafft eine kurze Anpassung der Mosquitto-Konfiguration:

  1. Öffnen Sie die Datei /etc/mosquitto/mosquitto.conf (bzw. in /etc/mosquitto/conf.d/) mit Root-Rechten.

  2. Kommentieren Sie alle Zeilen mit bind_address 127.0.0.1 oder listener 1883 aus, damit keine doppelten Listener-Definitionen mehr existieren.

  3. Fügen Sie an geeigneter Stelle (z. B. am Ende) folgende Direktiven ein:

    listener 1883
allow_anonymous true

    → listener 1883 sorgt dafür, dass Mosquitto auf allen Netzwerk-Interfaces (0.0.0.0) lauscht.
    → allow_anonymous true erlaubt Clients, sich ohne Benutzername und Passwort zu verbinden.

  4. Speichern Sie die Datei und starten Sie den Dienst neu:
    sudo systemctl restart mosquitto


  5. Überprüfen Sie mit:
    sudo lsof -i TCP:1883
    dass jetzt *:1883 (LISTEN) anstatt wie zuvor nur localhost:1883 (LISTEN) angezeigt wird.

Anschließend sollten mosquitto_pub- und mosquitto_sub-Befehle von jedem Rechner im gleichen Subnetz erfolgreich durchgehen, ohne dass die Verbindung zunächst abgelehnt wird.
