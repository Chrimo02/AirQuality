Dockerfile Backend - CM

Zweck und Kontext

Dieses Dockerfile dient zum Aufbau eines isolierten Containers für das FastAPI-Backend des Projekts Airquality-Monitoring. Es erstellt eine saubere, reproduzierbare Laufzeitumgebung mit Python 3.11.2, in der alle benötigten Abhängigkeiten installiert sind und das Backend über den ASGI-Server Uvicorn gestartet wird.

Dockerfile-Inhalt

FROM python:3.11.2

WORKDIR /app

COPY requirements.txt ./
RUN pip install --no-cache-dir -r requirements.txt

COPY . .

EXPOSE 8000

CMD ["uvicorn", "api:app", "--host", "0.0.0.0", "--port", "8000"]


Erläuterung der einzelnen Anweisungen

FROM python:3.11.2Nutzt das offizielle Python-Basisimage in Version 3.11.2.
WORKDIR /appLegt das Arbeitsverzeichnis innerhalb des Containers auf /appfest.
COPY requirements.txt ./Kopiert die Datei mit Python-Abhängigkeiten (requirements.txt) ins Arbeitsverzeichnis.
RUN pip install --no-cache-dir -r requirements.txtInstalliert alle Python-Abhängigkeiten ohne Cache, was das Image schlank hält.
COPY . .Überträgt den kompletten Backend-Code in den Container.
EXPOSE 8000Macht Port 8000 des Containers für eingehende HTTP-Anfragen erreichbar.
CMD ["uvicorn", "api:app", "--host", "0.0.0.0", "--port", "8000"]Startet den Uvicorn-Server mit der Anwendung api:app auf allen Netzwerkschnittstellen.

Hinweise zur Wartbarkeit

  • Bei Änderungen an den Abhängigkeiten immer die requirements.txt aktualisieren, um die Konsistenz des Containers zu gewährleisten.

  • Für kleinere Images empfiehlt sich ggf. später ein Umstieg auf python:3.11-slim.

Zusammenfassung

Das Dockerfile sorgt für eine stabile, standardisierte Laufzeitumgebung, die speziell auf das Backend des Airquality-Monitoring-Projekts abgestimmt ist. Durch die klaren und einfachen Anweisungen bleibt das Image wartbar und gut lesbar.
