Device Steuerung durch WLAN-Steckdosen - SK

Ziel

Das Ziel ist es, Geräte basierend auf der aktuellen Luftqualität automatisch zu steuern. Dazu haben wir einen Ventilator und einen Aroma Diffusor bzw Luftbefeuchtiger, die je über eine WLAN-Steckdose gesteuert werden können.

Umsetzung

Python Library

Die WLAN-Steckdosen sind das Modell TP-Link Tapo P100. Für diese gibt es einige Python Libraries, die man in Betracht ziehen kann, wie z.B. PyP100, pytapo. Allerdings funktionierte die Standardinstallation per pip zum Zeitpunkt der Implementierung nicht, da unsere Steckdosen bereits die Firmware-Version 1.2.5 mit neuer Authentifizierungsmethode verwendeten – welche von den offiziellen Libraries noch nicht unterstützt wurde. Dieses Fork von PyP100 hat schließlich zum Erfolg geführt: https://github.com/almottier/TapoP100

tp100_controller.py (WLAN-Steckdosen Controller)

Dieses Modul stellt eine Python Klasse TP100Controller zur Verfügung, mit der eine P100 WLAN-Steckdose gesteuert werden kann. 

Dazu kann man sich mit dem Gerät mithilfe der Tapo App Anmeldedaten verbinden, das Gerät ein- und ausschalten und den Status abfragen, ob das Gerät eingeschaltet ist.

from PyP100 import PyP100

# Daten aus Tapo App
TP100_IP = ""
TAPO_EMAIL = ""
TAPO_PASSWORD = ""

class TP100Controller:
    def __init__(self, ip, email, password):
        self.p100 = PyP100.P100(ip, email, password)
        self._login()

    def _login(self):
        try:
            self.p100.handshake()
            self.p100.login()
        except Exception as e:
            raise RuntimeError(f"Verbindung fehlgeschlagen: {e}")

    def turn_on(self):
        self.p100.turnOn()

    def turn_off(self):
        self.p100.turnOff()

    def get_status(self):
        info = self.p100.getDeviceInfo()
        return "on" if info.get('device_on', False) else "off"

    def get_name(self):
        return self.p100.getDeviceName()

air_control_rules.py (Regeln zur Steuerung)

In diesem Modul sind Regeln definiert, wann der Ventilator und der Diffusor an und aus sein sollte. Dazu wurden wieder die Messwerte (measurements), die auch für das Air Quality Rating verwendet werden, jedoch ohne Temperatur, da dieser Faktor nicht durch unsere Geräte steuerbar ist, benutzt.   

Es gibt für jedes Gerät zwei Methoden.

Ventilator

Die Methode needs_ventilation beschreibt, wann der Ventilator eingeschaltet sein sollte. Das ist der Fall, wenn mindestens einer der vier Werte (PM2.5, CO2eq, VOCAQI, HUMID) mit schlecht oder sehr schlecht bewertet ist. Wenn der SessionType OUTDOOR ist, aktiviert sich der Ventilator nicht, weil eine aktive Lüftung im Außenbereich keinen Einfluss auf die Umgebungsluft hat. Auch erwähnt sollte sein, dass ein Ventilator an sich die Luftqualität nicht verbessert, da er im Grunde nur die Luft umwirbelt. Der Gedanke hier ist, dass man den Ventilator mit lüften verbindet, um frische Luft schneller in den Raum zu bringen.

ventilation_not_needed schaltet den Ventilator aus, wenn alle vier Werte sehr gut oder gut sind. Eine mäßige Bewertung wurde bewusst in beiden Methoden nicht beachtet, da dies keinen zwingenden Handlungsbedarf erfordert und  um ein häufiges Umschalten des Ventilators zu vermeiden.

Diffusor

Aus demselben Grund wie beim Ventilator wird der Diffusor bei Outdoor-Sessions nicht geschaltet. Bei normaler Nutzung eines Aroma Diffusors (wenn man mehr als nur Wasser benutzt) sollte man vorsichtig sein, da dieser die Luftqualität sogar verschlechtern kann. 

Darauf wurde in der Steuerung geachtet und deswegen ist die Vorraussetzung für die Aktivierung des Aroma Diffusor, dass die Luftqualität an sich gut ist, d.h. wenn PM2.5 schlechtestens mäßig ist und VOCAQI schlechtestens gut ist, damit der Aroma Diffusor keine Belastung ist. Wenn diese Vorraussetzung erfüllt ist und die Luft zu trocken ist (< 30% Luftfeuchtigkeit), dann gibt diffusor_should_be_on True zurück.

Wenn also die Luftfeuchtigkeit sehr gut ist oder VOCAQI oder PM2.5 schlecht bis sehr schlecht ist, wird der Aroma Diffusor deaktiviert.
