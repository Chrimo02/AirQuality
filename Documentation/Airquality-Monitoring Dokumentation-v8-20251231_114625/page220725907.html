Versionsverwaltung & Projektstruktur - PP

1. Projekt-Repository und Git-Workflows

  • Repository-Klonen
    Das zentrale Repository wurde mit folgendem Befehl geklont:


    git clone <repo-url>


    (URL ggf. durch Bitbucket-URL ersetzen.)

  • Alltägliche Git-Kommandos

    • Änderungen werden mit git add zur Staging-Area hinzugefügt.

    • Mit git commit -m "Commit-Message" werden Änderungen lokal gespeichert.

    • Über git push werden die Commits ins Remote-Repo übertragen.

    • Um den aktuellen Stand vom Server zu holen, wird git pull verwendet.

  • .gitignore
    Die Datei .gitignore enthält Regeln, um temporäre Dateien, virtuelle Umgebungen und andere nicht relevante Daten aus dem Repo auszuschließen, z. B.:


    __pycache__/
*.pyc
*.db
*.log
venv/



2. Virtuelle Umgebung & Abhängigkeiten

  • Virtuelle Umgebung anlegen
    Mit folgendem Befehl wurde die venv im Projektordner erstellt:

    python -m venv venv

    (Wichtig: venv liegt innerhalb des Repos, ist aber per .gitignore ausgeschlossen.)

  • Requirements-Datei
    Nach jeder Paketinstallation mit pip wurde die requirements.txt durch

    pip freeze > requirements.txt

    aktualisiert. Sie enthält alle benötigten Python-Abhängigkeiten für die Reproduktion der venv.
