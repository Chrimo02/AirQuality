API - SK

Überblick

api.py ist das zentrale Backend des Air‑Quality‑Monitor‑Projekts und bildet die REST‑/WebSocket‑Schnittstelle für das Frontend. Es basiert auf FastAPI und kümmert sich um

  • Continuous Live‑Daten‑Streaming vom Luftsensor

  • Persistenz über SQLite

  • Gerätesteuerung (Ventilator & Aroma‑Diffusor)

  • MQTT‑Weiterleitung des Luftqualitäts‑Ratings

FastAPI wurde gegenüber Flask gewählt, da es eine bessere native Unterstützung für WebSockets bietet, was für die zuverlässige Echtzeitübertragung der Sensordaten entscheidend ist.

Zentrale Methoden

Startup & Initialisierung

  • Initialisiert Datenbank, Sensor, MQTT‑Client und holt sich den aktuellen Status der WLAN-Steckdosen.
  • Startet die beiden Hintergrund‑Tasks live_data_loop() und mqtt_reconnect_loop().


@app.on_event("startup")
async def startup_event():
    global sensor_reader, mqtt_client
    conn = init_db()
    conn.close()
    
    try:
        sensor_reader = SensorReader()
        print("Sensor erfolgreich initialisiert")
    except Exception as e:
        print(f"Sensor konnte nicht initialisiert werden: {e}")
        sensor_reader = None

 try:
        ventilator = TP100Controller(VENTILATOR_IP, TAPO_EMAIL, TAPO_PASSWORD)
        diffusor = TP100Controller(DIFFUSOR_IP, TAPO_EMAIL, TAPO_PASSWORD)
        last_vent_state = ventilator.get_status()
        last_diff_state = diffusor.get_status()
    except Exception as e:
        print(f"Fehler beim Abrufen des Gerätestatus beim Start: {e}")

    try:
        mqtt_client = MQTTClient(MQTT_BROKER, MQTT_PORT, MQTT_TOPIC)
        print(f"MQTT Client verbunden mit {MQTT_BROKER}:{MQTT_PORT}, Topic: {MQTT_TOPIC}")
    except Exception as e:
        print(f"MQTT Client konnte nicht verbunden werden: {e}")
        mqtt_client = None
    
    asyncio.create_task(live_data_loop())
    asyncio.create_task(mqtt_reconnect_loop())

Zentraler Loop

Die Funktion live_data_loop() bildet das Herz des Systems: Er sorgt dafür, dass Messdaten im Sekundentakt zu aussagekräftigen Informationen werden, bei Bedarf Geräte ansteuert und alle Ergebnisse sofort an UI & IoT verteilt.

Schritt

Hauptverantwortung

Was passiert

1 Erfassen

Sensordaten einsammeln

Jede Sekunde liest sensor_reader.lese_daten() eine kommagetrennte Key-Value Liste ("Rohzeile").

2 Umwandeln

Rohzeile→ Python‑Dict

sensor_reader.parse_sensor_line(raw_line)transformiert die eingelesene Rohzeile in ein Python-Dict.

3 Persistieren

In Datenbank schreiben

Läuft eine Session, speichert insert_data() die Rohzeile + Timestamp in SQLite. 

4 Extrahieren

Bewertungsmesswerte extrahieren

sensor_reader.get_rating_measurements(raw_line) filtert die fünf Parameter, die für die Luftqualitäts‑Regeln relevant sind (PM2.5, CO2eq, VOCAQI, TEMP, HUMID).

5 Bewerten

Luftqualitätratings berechnen

AirQualityRules vergleicht Messwerte mit Schwellen und erzeugt ein Gesamt‑Rating und Ratings der Bewertungsmesswerte („SEHR GUT“ … „SEHR SCHLECHT“). 

6 Veröffentlichen

Ampel mit MQTT steuern

Das Gesamt‑Rating wird an ein MQTT‑Topic gepublisht und steuert Ampel.

7 Steuerung

Geräte automatisch steuern

AirControlRules entscheidet anhand des Ratings, ob Ventilator und Aroma‑Diffusor per TP100‑Steckdose ein‑/aus­geschaltet werden, falls der automatische Modus aktiviert ist.

8 Aufbereiten & Verteilen

Daten für Frontend aufbereiten und broadcasten

Ein JSON‑Payload (Messwerte, Ratings, Farben, Aktor‑Status …) wird an alle WebSockets gebroadcastet.

9 Takten & Resilienz

Loop stabil halten

`await asyncio.sleep(1)` stellt 1 Hz sicher. Ein globales `try/except` fängt Fehler ab; nach kurzer Wartezeit (5 s) startet der nächste Zyklus – der Dienst bleibt dauerhaft online.

Bemerkung zur Bewertung:

Bei AirQualityRules kann man zwischen Indoor und Outdoor Regeln entscheiden. In api.py wird standardmäßig die Indoor Regeln verwendet, da dies der typische Anwendungsfall ist. Wenn eine Outdoor Session aktiv ist, werden hingegen die Outdoor Regeln verwendet. get_air_quality_rules() holt sich dabei von der aktuellen Session den Typ (Indoor/Outdoor) und dementsprechend gibt es die passenden Regeln von AirQualityRules zurück.

async def live_data_loop():
    global current_session_id, mqtt_client
    global ventilator_auto, diffusor_auto, last_vent_state, last_diff_state

    while True:
        try:
            if not sensor_reader:
                await asyncio.sleep(1)
                continue

            raw_line = sensor_reader.lese_daten()
            if not raw_line:
                await asyncio.sleep(1)
                continue

            # Vollständige Parser-Daten holen
            parsed = sensor_reader.parse_sensor_line(raw_line)

            # Wenn Session aktiv, Raw-Line in DB speichern
            if current_session_id:
                conn = get_db_connection()
                from database.save_data import insert_data
                insert_data(conn, raw_line, current_session_id)
                conn.close()

            # Nur die fünf Schlüsselmesswerte für die Rating-Logik extrahieren
            rating_vals = sensor_reader.get_rating_measurements(raw_line)

            # Gesamt- und Einzel-Rating berechnen
            rules = get_air_quality_rules()
            overall_quality = rules.get_overall_air_quality(rating_vals)
            overall_quality_str = air_quality_to_string(overall_quality)

            # MQTT Publish
            if mqtt_client:
                try:
                    mqtt_client.publish(overall_quality_str)
                except Exception as e:
                    print(f"Fehler beim MQTT Publish: {e} - MQTT Client wird neu verbunden")
                    mqtt_client = None # löst den reconnect im mqtt_reconnect_loop() aus

            # Automatische Steuerung
            control_rules = get_air_control_rules()
            if ventilator_auto:
                global last_vent_state
                if control_rules.needs_ventilation(rating_vals) and last_vent_state != "on":
                    TP100Controller(VENTILATOR_IP, TAPO_EMAIL, TAPO_PASSWORD).turn_on()
                    last_vent_state = "on"
                elif control_rules.ventilation_not_needed(rating_vals) and last_vent_state != "off":
                    TP100Controller(VENTILATOR_IP, TAPO_EMAIL, TAPO_PASSWORD).turn_off()
                    last_vent_state = "off"

            if diffusor_auto:
                global last_diff_state
                if control_rules.diffusor_should_be_on(rating_vals) and last_diff_state != "on":
                    TP100Controller(DIFFUSOR_IP, TAPO_EMAIL, TAPO_PASSWORD).turn_on()
                    last_diff_state = "on"
                elif control_rules.diffusor_should_be_off(rating_vals) and last_diff_state != "off":
                    TP100Controller(DIFFUSOR_IP, TAPO_EMAIL, TAPO_PASSWORD).turn_off()
                    last_diff_state = "off"

            print(
                "[DEBUG] Steckdosen  |  "
                f"Ventilator: {'AUTO' if ventilator_auto else 'MAN'} / {last_vent_state or 'unknown'}   ||   "
                f"Diffusor: {'AUTO' if diffusor_auto else 'MAN'} / {last_diff_state or 'unknown'}"
            )

            ratings = {}
            for param, val in rating_vals.items():
                rating = rules.rate_parameter(val, param)
                ratings[param] = {
                    'value': val,
                    'rating': air_quality_to_string(rating),
                    'color': get_air_quality_colors()[air_quality_to_string(rating)]
                }

            measurements_all = {
                k: v for k, v in parsed.items()
                if isinstance(v, (int, float))
            }

            # Payload bauen und broadcasten
            live_data = {
                'timestamp': datetime.now().isoformat(),
                'measurements': measurements_all,
                'air_quality_rating': ratings,
                'overall_quality': overall_quality_str,
                'overall_color': get_air_quality_colors()[overall_quality_str],
                'parsed_data': parsed,
                'session_type': get_current_session_type().value,
                'ventilator_auto':  ventilator_auto,
                'diffusor_auto':    diffusor_auto,
                'ventilator_state': last_vent_state,
                'diffusor_state':   last_diff_state
            }
            await broadcast_live_data(live_data)

            await asyncio.sleep(1)

        except Exception as e:
            print(f"Error in live data loop: {e}")
            await asyncio.sleep(5)

Bemerkung zu TP100Controller:

Das TP100Controller-Objekt wird gezielt nur dann erzeugt, wenn eine Steueraktion tatsächlich erforderlich ist. Wir verzichten bewusst auf globale Instanzen, da eine Verbindung zur Steckdose nur im Moment der Steuerung benötigt wird. So bleiben Verbindungsfehler auf einzelne Steuerbefehle begrenzt, ohne das Gesamtsystem zu beeinträchtigen.

Websocket

WebSocket /ws/live-data 

  • Der Client baut einmalig eine WS‑Verbindung zum Server auf.
    await websocket.accept() bestätigt den Handshake.

  • Der verbundene Socket wird in die globale Liste websocket_connections aufgenommen.
    So behält das Backend alle offenen Kanäle im Blick.

  • Danach wartet die Coroutine mit await websocket.receive_text() auf eingehende Nachrichten.
    Der Server erwartet aber nichts – der Aufruf blockiert lediglich, bis der Client die Verbindung schließt.
    Ergebnis: Push‑Only‑Kanal ohne Ping‑Pong‑Logik.

  • Im finally‑Block wird der Socket wieder aus der Liste entfernt, egal ob der Client sauber schließt oder die Verbindung abreißt.
    Damit verhindert man Speicher‑/Listenleichen.


@app.websocket("/ws/live-data")
async def websocket_endpoint(websocket: WebSocket):
    await websocket.accept()
    websocket_connections.append(websocket)
    try:
        await websocket.receive_text()
    finally:
        if websocket in websocket_connections:
            websocket_connections.remove(websocket)

broadcast_live_data(data) 

  • Wird jede Sekunde vom Live‑Data‑Loop aufgerufen.
    Liefert ein JSON‑Serialisat des Mess‑Snapshots an alle aktuell verbundenen Clients.

  • Sofortiger Exit, wenn niemand verbunden ist ⇒ spart CPU.

  • Die Liste wird vor dem Iterieren kopiert (connections_copy).
    Grund: Parallel könnten andere Koroutinen denselben Pool verändern (Clients verbinden/trennen).
    Die Kopie schützt vor „size changed during iteration“.

  • Fehler‑Handling pro Socket:
    try … except fängt z. B. „Broken pipe“ ab, loggt den Fehler und entfernt nur den betroffenen Socket.
    So bleibt der Broadcast für alle übrigen Clients intakt.

  • Serialisierung mit json.dumps(data) unmittelbar vor dem Senden; Clients erhalten reine Textframes.


async def broadcast_live_data(data: Dict[str, Any]):
    if not websocket_connections:
        return
    
    connections_copy = websocket_connections.copy()
    
    for websocket in connections_copy:
        try:
            await websocket.send_text(json.dumps(data))
        except Exception as e:
            print(f"Error sending to WebSocket: {e}")
            if websocket in websocket_connections:
                websocket_connections.remove(websocket)

API Server starten


uvicorn api:app --host 0.0.0.0 --port 8000

Dieser Befehl startet das FastAPI-Backend mit dem ASGI‑Server Uvicorn und macht die API im lokalen Netzwerk unter Port 8000 verfügbar.
ASGI (Asynchronous Server Gateway Interface) ist der moderne Standard für asynchrone Python‑Webanwendungen und ermöglicht u. a. WebSockets und gleichzeitige Verbindungen.
