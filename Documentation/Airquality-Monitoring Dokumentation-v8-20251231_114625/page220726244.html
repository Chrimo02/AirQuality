Testing & Qualitätssicherung - PP

1. Teststruktur und -aufbau

Das Projekt verwendet das pytest-Framework für Unit-Tests. Alle Tests befinden sich gesammelt im Ordner tests/:

  • test_db_helper.py:
    Prüft die Datenbankinitialisierung, Session-Start/-Ende, Duplikatvermeidung usw.

  • test_save_data.py:
    Testet das Schreiben von Messwerten und Logfiles sowie das Insert in die Datenbank.

  • test_read_sensor_data.py:
    Simuliert das Lesen von Sensordaten, DummySerial, Parsing und Extraktion der Werte.

Alle Tests nutzen temporäre Datenbanken und Dateien, sodass beim Testen keine echten Produktionsdaten überschrieben werden.

2. Testausführung

Um alle Tests auszuführen:

  1. Virtuelle Umgebung aktivieren (falls genutzt):

    source venv/bin/activate


  2. In das Projekt-Hauptverzeichnis (eine Ebene über tests/) wechseln:

    cd <projekt-root>


  3. Pytest starten:

    pytest -q


Pytest sucht dabei automatisch nach allen Dateien, die mit test_ beginnen, und führt alle enthaltenen Tests aus.

3. Besondere Testmethoden und Tools

  • Es werden Fixtures für temporäre Datenbanken (tmp_path, monkeypatch) verwendet, um ein sauberes Testumfeld zu gewährleisten.

  • Für die Sensorik wird eine DummySerial-Klasse mit monkeypatch als Ersatz für den echten Sensor genutzt, damit Tests unabhängig von echter Hardware laufen können.

  • Es wird geprüft, dass Logfiles geschrieben werden und dass die wichtigsten Ausgaben tatsächlich auf der Konsole erscheinen.

4. Beispiel-Testfall (test_save_data.py)

def test_insert_data_and_log(tmp_path, conn, capsys, monkeypatch):
    raw = "PM1.0,1.1,PM2.5,2.2,PM10,3.3,TEMP,20,HUMID,50"
    sid = start_session(conn, "SessionX", None)
    insert_data(conn, raw, sid)
    cur = conn.cursor()
    cur.execute("SELECT pm1_0, pm2_5, pm10, session_id FROM air_data")
    pm1, pm2p5, pm10, sess = cur.fetchone()
    assert pm1 == 1.1
    assert pm2p5 == 2.2
    assert pm10 == 3.3
    assert sess == sid


5. Typische Fehlerbilder beim Testen und Lösungen

  • ImportError für lokale Module:
    → Tests immer aus dem Projekt-Root starten, __init__.py-Dateien in jedem Ordner anlegen.

  • DB wird nicht überschrieben:
    → Über tmp_path und Monkeypatch werden temporäre Datenbanken verwendet.

  • Hardwareabhängige Fehler:
    → DummySerial und Fixtures ersetzen echte Sensorik beim Testen.

6. Aktualisieren der requirements.txt

Nach Installation neuer Pakete:

pip freeze > requirements.txt


→ So sind alle Test-Abhängigkeiten dokumentiert und reproduzierbar

Mit diesem Testkonzept ist die Codequalität abgesichert, und Fehler werden frühzeitig im Entwicklungsprozess erkannt.
